# ADR-0002: 订单提交采用启动对账后的 fail-closed 闸门

- **Status:** Accepted
- **Date:** 2026-11-17
- **Scope:** 账户初始化、订单提交、断线恢复和人工复核

## Context

线上服务可能在重启、断线、回调竞态、查询失败或本地账本与券商状态不一致时继续收到策略信号。直接重试或信任旧状态可能导致重复订单、漏记成交或错误持仓。

## Decision

- `OrderManager` 创建时关闭提交。
- 连接和订阅成功后先查询券商订单、成交、资产和持仓。
- 只有干净对账、账户校验和风险检查通过后才打开提交闸门。
- 未知券商订单、缺失本地订单、查询错误、断线竞态或人工复核均保持关闭。
- `ManagedTrader` 只能把旧式调用转换为统一订单意图，不能绕过闸门。
- 恢复监督器重连后必须再次对账，不沿用断线前的放行状态。

## Alternatives considered

1. 重连后立即恢复下单：可能使用过期状态，拒绝。
2. 只依赖策略自身去重：无法覆盖多进程、回调和券商侧未知订单，拒绝。
3. 发生错误时自动清空本地账本：破坏审计和对账证据，拒绝。

## Consequences

- 安全优先，可能在不确定状态下牺牲部分交易机会。
- 需要可靠的券商查询、SQLite 账本和人工复核流程。
- 订单、恢复和风险代码必须保持幂等和可审计。

## Validation and rollback

使用假网关和临时 SQLite 覆盖重复意图、重复成交、断线、未知订单、查询错误和风险拒单测试。任何放宽闸门的改动都需要新的 ADR 和专门验收窗口。
