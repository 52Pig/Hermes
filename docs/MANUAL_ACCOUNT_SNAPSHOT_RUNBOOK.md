# 人工账户快照运行手册

> **Document type:** manual-account operating runbook
> **Audience:** operators, reviewers, incident responders
> **Scope:** 无法使用受支持账户查询/提交接口时的人工快照与人工确认流程
> **Reviewed:** 2026-11-17

## 1. 适用边界

本手册描述人工账户快照模式，不代表 Hermes 的唯一线上模式。当前 Hermes 也包含 QMT/xtquant 连接、订单协议和恢复对账代码；使用哪种模式必须由部署配置和操作授权决定。

人工模式下，流程是：

```text
券商官方终端 -> 人工抄录快照 -> Hermes 校验/推理 -> 人工核对订单建议
             -> 券商官方终端下单 -> 人工抄录成交 -> 本地账本对账
```

人工模式只生成观察结果和订单建议，不应绕过统一订单闸门提交订单。`go_live` 或等价开关必须保持关闭。

## 2. 每个交易日流程

### 开盘前

1. 在券商官方终端确认账户和交易日。
2. 记录账户编号、快照时间、现金、可用现金、冻结现金、总资产，以及每个持仓的证券代码、总数量、可卖数量、成本价和市值。
3. `as_of` 必须是终端显示的带时区时间，不能使用文件创建时间代替。
4. 保存为独立 JSON，例如 `account_snapshot_<date>.json`；不要提交到仓库。
5. 使用 `write_manual_snapshot_template` 生成模板，或按本手册的 schema 填写。

### 推理和人工确认

1. 使用 `load_manual_account_snapshot(path, expected_account_id=...)` 校验快照。
2. 校验失败时停止生成新的买入建议，修正快照后重新开始。
3. 将通过校验的账户快照、行情、策略/模型版本和快照哈希送入推理流程。
4. 人工逐单核对证券代码、方向、数量、价格类型、T+1 可卖数量、涨跌停和风险预算。
5. 订单清单必须保留模型/策略版本、账户快照哈希和人工确认记录。

### 收盘后

1. 从券商官方终端抄录实际成交、未成交、撤单和费用。
2. 回填本地账本，重新计算持仓、现金和 NAV。
3. 对齐券商快照、本地账本和策略状态。
4. 下一交易日前先完成对账，再生成新的订单建议。

## 3. JSON 最小格式

```json
{
  "account_id": "ACCOUNT_PLACEHOLDER",
  "currency": "CNY",
  "as_of": "2026-11-08T14:50:00+08:00",
  "cash": 100000.0,
  "available_cash": 90000.0,
  "frozen_cash": 1000.0,
  "margin_used": 0.0,
  "equity": 110000.0,
  "positions": [
    {
      "symbol": "000001.SZ",
      "quantity": 100,
      "available_quantity": 100,
      "average_price": 10.0,
      "market_value": 2000.0,
      "today_quantity": 0,
      "yesterday_quantity": 100
    }
  ]
}
```

示例中的账户和价格均为占位数据。真实快照不得进入 Git、聊天记录或公共日志。

## 4. 强制停止条件

出现任一条件时，只保留观察和人工核对，不生成新的买入建议：

- 快照不是目标账户、缺少时区、来自未来或超过允许时效。
- 可用现金大于现金，或可卖数量大于持仓数量。
- 同一证券重复出现，或账户与本地成交账本无法对齐。
- 订单建议超出风险预算、单票上限、涨跌停或 T+1 可卖限制。
- 成交回填不完整，无法解释现金、持仓或 NAV 差异。
- 模型/策略版本、行情日期或快照哈希缺失。

未来若要自动实盘，必须先取得券商书面授权接口，并完成模拟盘、逐单成交、断线恢复和账本对账验收。
